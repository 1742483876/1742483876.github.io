01 · 先搞懂两件事

预训练 vs 中训练
一句话：先学世界，再学干活

可以把模型想象成一个学生。预训练是「从幼儿园读到高中」——大量泛读，建立语言、知识和基本推理； 中训练是「进大学选专业」——用更干净、更任务向的数据，把能力往 Agent、长文、代码、STEM 等方向拧。

Pretrain · 一阶段

目标：把「世界」装进模型

海量网页、书籍、论文。策略从「一刀切过滤」转向「轻质量过滤、重采样」： STEM 上采、热门学科下采、长尾簇用幂律插值。

  • 数据量级：万亿 token 级，追求覆盖与多样性
  • 上下文：通常较短（几 K～几十 K）
  • 核心动作：抓取 → 解析 → 去重 → 质量分层 → 采样配比
  • 你在周报里看到的：一阶段数据、Evaluation & Scaling ladder
Midtrain · 中训练

目标：把「干活」练到手上

在预训练底座上，用高质量、高密度的 topic 数据继续训。 上下文从 32k → 256k → 1M 递进，配比是零和博弈——加长文就要挤 STEM。

  • 数据量级：百亿～几万亿 token（典型中训练 256K 合版可到约数 T 文本（量级示意））
  • 上下文：32k / 256k / 1M，能力随窗口变难
  • 核心动作：按 topic 造数据 → 合版消融 → 长跑 derisk → 定版
  • 你在周报里看到的：代码 / STEM / 知识 / 长文 / Agent / VLM / 合版

02 · 假如目标是 1T 参数模型

一步一步该怎么做

参数量 1T（万亿）决定的是「模型有多大」；真正决定效果的，是数据配方、上下文递进、和评测是否可信。 下面按常见「正式版模型 + 中训练合版」节奏，写成可执行顺序。

01

先定「能力目标」，再定数据

产品需求 评测清单

写清楚：这个 1T 模型要赢哪些 bench（SWE、MRCR、SimpleQA、STEM、多模态……）， 以及不能掉哪些（纯文本、多语言）。没有目标，配比就是拍脑袋。

周报对照 · Evaluation & Scaling 小 ladder（22B 级）只能显著区分 U=40B→80B 这种量级的重复度差异。 评测分辨率不够时，你看不到策略好坏——先问「当前评测能不能测出差别」。
02

一阶段预训练：堆覆盖，但别一刀切

Pretrain 网页 / 书 / 论文 去重 · 采样

把互联网语料做成训练 bin：解析 → MinHash / 语义 / SAE 去重 → 质量分层 → 按学科幂律采样。 STEM 偏向上采；占比过高的热门学科下采；太稀疏的长尾别硬上采。

周报对照 · 一阶段 SAE 去重比 BGE 语义去重 +1.1pp，因为它自带质量筛选且对文档长度中立。 但 LiveCodeBench 提醒你：竞赛代码靠「同类模板反复曝光」强化——全局统一阈值去重会超额删掉算法簇。
03

用小模型 ladder 做数据策略实验

小 ladder val loss 伴生 SFT

别一上来就在 1T 上试配方。用可控小模型（常用小 ladder（数十亿激活量级））跑消融：改 U（unique support）、改配比、改去重强度， 看 validation loss–compute 曲线斜率。结论稳定后再放大。

周报对照 · 关键坑 ICL 和 SFT 经常打架（Midtrain Exp4：MRCR 上 ICL +22pp 但 SFT −11pp）。 团队已定调：后续以 SFT / val loss 为主，小尺寸 0/1-shot ICL 不导向真实能力。 另外 500B decay 可能暴露不出风险——中训练合版 在 1.1T 后才和 midtrain3 趋势分离。
04

按 Topic 造中训练数据（可并行）

Midtrain 代码 · STEM · 知识 · 长文 · Agent · VLM

每个 topic 是一条独立生产线：自然数据精筛 + 合成/改写 + 质量模型 + 专项 bench。 负责人分开，但最后要进同一张合版表。细节见下方「各 Topic」一节。

周报对照 · Midtrain 合版 配比是零和的：定版合版把长文浓度拉高后，Agent 与生产长文 bench 明显受益（量级示意）； 数学/科学/逻辑持平微负，因为 MATH/STEM 只换了 CoT、题池被挤占。
05

合版消融：一张表决定命运

合版多轮消融 32k 再 256k

把各 topic 数据按比例拼成合版，逐版调：下采某类 userlog、上采 STEM、补自然长文、压 replay…… 每一版只改一两件事，用伴生 SFT + domain bench 看涨跌。定版合版交付量级可达数 T 文本。

周报对照 · 消融结论 删掉金融/法律/医疗垂类后垂类评测居然持平、知识微正；logicqa 对逻辑是跷跷板却挤占 web； 小语种掐尖收益不大。→ 很多「看起来该上」的垂类数据，合版里未必划算。
06

上下文递进：32k → 256k → 1M

多模态上下文 stage 节奏 长文专项

按你们正式版节奏：先短后长。256k 是 Agent + 长文主战场；1M 补「有序定位 / 全量覆盖」—— 因为评测显示 64k–1M 各档从 6.4 掉到 0.5，模型会漏检、提前停、误判信息不存在。

周报对照 · 长文 Nextlong 从单主题召回改成多主题联合召回（真实长文是多主题交织的）； DRP 用 arxiv/wiki 拓扑反向合成研究轨迹；keychain 用 UUID 链强迫模型先「找到问题本身」。
07

长跑 derisk，再上 1T 正式训练

constLR 每 400B 伴生 SFT 扩到生产规模

在接近生产的设置下把合版跑长：观察 Agent / 长文是否持续 scale，有没有 ICL 假崩塌（合成数据初期模型 confuse 要不要输出 CoT）。 确认趋势后，用同一配方把模型规模拉到 1T，算力、并行策略、checkpoint 与数据管线一并升级。

周报对照 · 基础设施坑 H 卡镜像 2606 会导致 multi-epoch 从第 3 epoch 起 train loss 异常上升 → 用 2605.post3 / 2606.post3； Ceph 挂载未 fsync 会静默把 bin 里 token 写成 0 → grad-norm spike。大模型训练，基建翻车等于白烧卡。
08

后训练对齐（SFT / RL）接棒

SFT RL / RLHF 班车评测

Midtrain 交付的是「底座能力」；真正能对话、会用工具、守规矩，靠后训练。 详见下方「后训练」专章：SFT 教格式与跟随，RL 用反馈继续拧能力。

公开研究 · 数据量

训一个 1T 参数模型，大概要多少数据？

先分清两件事：参数量（模型有多大）和 token 量（看过多少字）。 「1T 模型」通常指约 10¹² 个参数；该喂多少 token，公开结论已经变了好几次。

口径经验公式对 1T 参数意味着…来源
计算最优（经典） ≈ 20 token / 参数 ≈ 20T tokens 论文 Hoffmann et al., Chinchilla, 2022 · arXiv:2203.15556
现代超训（常见） 几十～上百 token / 参数 远超 20T；看质量与重复策略，不是只堆字数 论文 Llama 3（约 15T tokens 训到 405B，远超 Chinchilla 比例）· arXiv:2407.21783
开源大模型近年量级 约 15T–20T+ 预训练 token Dense 1T 若对齐这个「时代标准」，预训练往往也是十几 T 起跳 论文 DeepSeek-V3 14.8T · arXiv:2412.19437；Qwen2.5 系列公开称预训练扩到约 18T（Max 称 20T+）
中训练（额外） 通常再加 0.5T–数 T 在底座之上继续训长文 / Agent / STEM 等；总量取决于目标能力 方法 行业惯例 + 内部脱敏 中训练合版常在数 T 量级
小白结论：若只问「计算最优下限」，Chinchilla 说大约 20× 参数 → 1T 参数约 20T token。 但 2024–2025 的强模型普遍故意多喂数据（超训），因为高质量数据 + 多看几遍往往更划算。 规划 1T 时：先按 15T–30T 预训练做预算，再单列 中训练数 T 与 后训练（SFT/RL，通常远小于预训练，但数据质量极高）。

如果总预算锁死，怎么切阶段？（示意）

阶段示意占比（相对总 token）干什么
预训练 / 一阶段70%–85%覆盖世界知识、语言、基础推理
中训练10%–25%代码 / 长文 / Agent / STEM / 知识密度
上下文扩展另计或并入中训练32k→256k→1M 等窗口拉长
后训练通常 <5%（但极贵）SFT + 偏好/RL，决定产品形态

示意表不是定理；公开论文很少给「1T 专用标准切分」。用途：帮你写预算，而不是照抄交付。

公开研究 · 配比

配比应该咋配？各 topic 大概多少？

没有全球统一答案。公开共识是：配比会显著影响下游，且领域之间会互相打架——所以要用小模型试，再放大。

论文

Llama 3 最终预训练配比（可当「通用底座」参考）

约 50% 通用知识、25% 数学与推理、17% 代码、8% 多语言。他们用小模型 scaling law 实验反复挑配比，训练中途还会上采样数学/非英、下采样低质子集。

arXiv:2407.21783
论文

RegMix / DoReMi：别只靠拍脑袋

RegMix（2024）用大量小模型 + 回归预测「哪种混合物更好」，再训大模型；称可用约 DoReMi 10% 算力达到可比效果。关键发现：配比可让单任务差到约 14.6%；网页语料与下游正相关往往强过「看起来更高质」的维基；领域交互常违背常识。

RegMix arXiv:2407.01492 DoReMi arXiv:2305.10429
内部脱敏

中训练合版：总预算固定 = 零和博弈

加长文/Agent 就会挤 STEM/知识；垂类数据未必涨垂类榜。实操是 Exp 逐版只改一两项，用伴生 SFT 裁决。

若总中训练预算 = 3T token，topic 怎么切？（教学示意）

下表是「面向 Agent + 长文产品」的示意配方，用来理解数量级；不是某家生产定版。数字按 3T 中训练总额估算。

Topic示意占比约合 token主要干什么
代码 + Agent 轨迹45%–65%1.4T–2.0TSWE / 工具调用 / 多步任务

STEM（题 + 论文书）8%–18%0.25T–0.55T数理化推理；只换 CoT 往往不够

小白操作流程（配比怎么「算」出来）

  1. 写下产品必须赢的榜（如 SWE、长文、SimpleQA）和绝不能掉的榜。
  2. 用小 ladder 扫 20–100 组配比（RegMix/人工网格都行）。
  3. 每组看：val loss + 伴生 SFT 后的 domain bench（别只看 0-shot ICL）。
  4. 放大到生产前做长跑 derisk；短训看不到的风险常在 1T token 之后才冒出来。
  5. 定版后冻结评测协议，避免「换榜车」导致假涨跌。

公开研究 · 多模态

VLM 怎么改造？从文本到「能看图」

多模态不是把图片随便塞进文本配比。公开强模型通常分阶段：先视觉编码器，再图文对齐，再端到端，并把 OCR / 交织图文 / 视频 / Agent 分开做质量。

阶段怎么切

常见三步：① 训 / 增强 ViT（视觉塔）；② 多模态数据对齐（caption、VQA、交织图文）；③ 解冻更多参数做端到端，并拉长上下文。 论文 Qwen2-VL / Qwen2.5-VL 技术报告描述了 native dynamic resolution 与分阶段训练。

数据要哪些

公开实践常覆盖：图文 caption、交织图文、OCR/文档、视觉知识、多模态题、定位/grounding、视频、GUI Agent。 Qwen2.5-VL 称预训练语料从约 1.2T 扩到约 4.1T 多模态相关 token，并在不同阶段调整各类占比。

后训练注意

Qwen2.5-VL 的 SFT 约 200 万条，条目上纯文本 : 多模态 ≈ 50:50，但多模态条目更吃 token/算力；其后还有 DPO。 训练时常见：ViT 在部分对齐阶段冻结，避免把视觉塔冲坏。

改造动作小白理解来源
Dynamic resolution / 动态分辨率 图不再强制缩成固定小格，按原图生成可变数量视觉 token，更接近「看得清细节」 Qwen2-VL arXiv:2409.12191
Interleaved 图文清洗 网页图文穿插很吵；要按「图文相关性 / 互补性 / 信息密度」打分过滤 Qwen2.5-VL arXiv:2502.13923
能力对齐检查 把评测与存量数据都打上能力标签（定位、计数、多图…），看缺口再补数 内部脱敏 Data Probe 思路
控制「加图」别伤纯文本 混训时盯纯文本榜；图比例过高可能拖垮语言能力，需要 replay 文本 方法 + 内部经验
先建多模态 val loss 小模型 few-shot 多模态分数很抖，配比搜索会缺信号 内部脱敏

公开论文 · 值得记住的 Insight

不止周报：外面已经验证过的结论

下面每条都尽量可点进原文。绿色标签 = 公开论文；橙色 = 内部脱敏经验（便于对照）。

Chinchilla 2022

算力固定时，模型和数据应大致同比放大

过小数据训过大模型 = 欠训。经验比例约 20 token/参数；但这是「计算最优」而非「质量最优上限」。

arXiv:2203.15556
Llama 3 2024

用小模型预测大模型的数据配比，再上正式训练

知识分类 + scaling law 实验选 mix；最终约 50/25/17/8（通用/数学推理/代码/多语言），训练中途还会动态调。

arXiv:2407.21783
RegMix 2024

配比是一等公民，且常常反直觉

自动搜索混合物；网页语料相关性可能强过「高端」维基；领域之间互相牵扯，需要整体建模而不是逐个加料。

arXiv:2407.01492
DeepSeek-V3 2024

强开源底座 ≈ 十五 T 量级高质量 token + 稳定训练

14.8T 预训练后做上下文扩展，再 SFT/RL。说明「大参数」仍要配「大数据 + 工程稳定性」。

arXiv:2412.19437
Qwen2.5-VL 2025

多模态要扩数据、分阶段，并认真洗交织图文

多模态预训练扩到约 4.1T；动态分辨率；SFT 条目 50/50 文/多模但算力不等价；交织数据需相关性打分。

arXiv:2502.13923
DoReMi 2023

按 domain 损失动态调采样权重

早期自动配比代表作之一：让模型在难学的 domain 上多看一点。后来 RegMix 等在算力效率上继续推进。

arXiv:2305.10429

03 · 你需要准备什么

开训前的物资清单

没有这些，1T 只是一个数字。下面按「人 / 数据 / 算力 / 评测 / 工程」五类列清楚。

01 · 人

Topic Owner 矩阵

代码、STEM、知识、长文、Agent、VLM、合版各有人盯。合版 owner 拍板配比；评测 owner 保证 ICL/SFT 协议一致。

02 · 数据

一阶段池 + Topic 池

预训练语料（网页/书/PDF）、权威垂类源、回流 userlog、合成管线（改写 / Nextlong / STEM 出题 / PR 相关文件）。

03 · 算力

小 ladder + 生产集群

小模型消融集群日常跑；正式 1T 需要大规模并行。合版长训要预留足够长的训练窗口，短训看不到的风险往往要跑到万亿 token 后才暴露。

04 · 评测

Bench + Val Loss + 伴生 SFT

Domain bench、生产 bench、能力打标评测、validation set。能力粒度打标（VLM Data Probe）比只堆 benchmark 更管用。

05 · 工程

解析 · 去重 · Bin · 镜像

PDF/网页解析、commit 管线、泄题检测、dataloader、稳定镜像与存储 fsync。管线 bug 会直接污染万亿 token。

06 · 节奏

Topic → 合版 → 定版 → 生产

对齐你们四阶段：多模态上下文 stage1 纯 VLM → stage2-32k → stage3-256k → stage4-1M。每阶段三拍：交付、合版、定版。

代码 · 自然代码比样板题更值钱

commit / PR / release

教模型读真实改动：commit 消息 + diff、PR 描述 + 相关文件、release note。 目标直接对齐 SWE 一类「改仓库」能力。

怎么做

  • 修管线：latin1 乱码、二进制识别、非源码打标前置
  • 抓取前用 commit msg 规则过滤（你们合过滤 44.6%，低质率 88.6%）
  • 质量模型打分（coherence、任务分类 20 类）
  • PR 拼相关文件：一跳依赖 + 文件 BM25 + 消息 BM25
  • commit↔PR 按 sha 去重（留存约 89%，比 minhash 狠得多）
「补上下文的收益远大于再筛一层质量：相关文件让 SWE Verified +1.93pp、pass@3 +4pp；再分层筛选反而退化。」 来源 · Midtrain 专项 02-代码 / P1 周报 CodePretrain

STEM · 筛选策略会系统性误伤学科知识

自然精筛 + 高难度合成

一边把网页/书/论文里的数理化生捞准，一边合成 PhD 级难题。注意：通用「高推理价值」阈值会丢掉分类学这类核心知识。

怎么做

  • 粗召回（学科）→ 精筛；按源+学科让专家 review Save/Drop
  • 数据库结构化条目改写成连贯自然语言
  • 物化：论文 → Synth → Answer/Judge → Filter
  • 数学 Hard：小模型解 5 次，任一失败即 Hard
  • 幻觉检测压到 <1%；合版时 STEM 只换 CoT 不够，要扩题池
「生物书籍 Drop 端漏召 42%——因为策略硬性要求推理价值≥高，而形态描述天然不满足，却是学科核心。」 来源 · Midtrain 专项 03-STEM

知识 · 去重可能删掉权威、留下低质副本

垂类知识 · 百科 · 改写

金融/法律/医疗权威源重建、维基 talk/pageinfo 质量分层、阅读理解与 Meta Prompt 改写。目标抬 SimpleQA 类事实能力。

怎么做

  • 从原始爬取池回捞权威站，重解析（曾一次新增 216B token）
  • 法律：裁判说理作高价值 token 打分；医疗：病程记录串联 7 表
  • 知识点扩增（回流 bad case）→ 大池召回 → 多风格改写
  • 垂类合版消融：未必涨垂类 bench，却可能挤占通用知识
「去重把权威版本判成重复删掉，留下低质副本——金融/法律/医疗三个垂域都中了这个招。」 来源 · Midtrain 专项 05-知识

长文 · 窗口变长，能力会先塌再补

Nextlong · ACC · DRP · 1M

教模型在超长上下文里定位、全量覆盖、状态追踪。256k 主战场；1M 补短板。

怎么做

  • Nextlong：多主题联合召回拼长文（别只按单主题）
  • ACC：检索 / 多文档 QA / 状态追踪，从回流轨迹重组
  • DRP：用引用拓扑反向合成 Deep Research 轨迹
  • 1M：有序定位（timeline）+ 全量覆盖（multi-query / keychain）
  • 注意 baseline 越强，合板增益空间越窄（更小模型 → 更大一点的 ladder）
「64k–1M 三档得分从 6.4 掉到 0.5：漏检、提前停、误判信息不存在——这是造 1M 数据的动机。」 来源 · Midtrain 专项 06-长文

Agent · 同源轨迹不一定该去重

userlog / traj

用真实工具调用轨迹教模型做事。处理回流时，同一 session 的不同加工方式可能互补。

怎么做

  • 按 session / query minhash 做内部去重
  • 与其他团队同源数据：先做对照实验再决定是否 dedup
  • 合版里 Agent 占比高（常与 code 合计 60%+），要单独长跑 derisk
  • 交付定版后盯 SWE / Terminal / Search Agent 族
「重复的是来源，不是内容：jadeqt+jura 混合在近一半 生产 bench 维度最好。」 来源 · Midtrain 专项 07-Agent

VLM · 图文一起训，文本别被拖垮

多模态 midtrain

视觉 STEM、OCR 长文档、GUI Agent、带图轨迹。用 Data Probe 把评测下沉到能力粒度，对齐存量数据缺口。

怎么做

  • 先纯 VLM stage，再 LLM+VLM 混训（你们 stage1→2）
  • 加图比例控制在一定范围（周报：约 20% 内不影响纯文本）
  • 能力打标：暴露 Grounding 过简、多图缺失等缺口
  • few-shot 小模型波动大 → 先建多模态 val loss
「存量 Grounding 65.9% 只是类别指代，评测里动作/序数/关系却占 25.6%——数据分布和考卷对不上。」 来源 · P1 周报 VLM

合版 · 数据工作的实质是分配

配比表 · 消融 · 定版

总 token 预算固定时，加任何 topic 都在挤别的。合版 owner 用实验把「想要的涨点」变成可交付的 OnePage。

怎么做

  • 定 baseline → Exp 逐版改一两项
  • 同时看伴生 ICL、伴生 SFT、val loss、domain bench
  • 对「假崩塌」做 few-shot derisk（合成数据 confuse CoT）
  • 长跑确认 scale 后再交付生产 bin
  • 回流合成数据清洗其他模型 special token
「定版合版：Agent 与长文明显受益；数学科学逻辑微负——符合「只换 CoT、被挤占」的预期。」 来源 · Midtrain 专项 09-合版 / P1 周报 Midtrain

一阶段 · 采样策略取代一刀切过滤

Pretrain 主线

1T 模型的「世界观」主要在这里形成。中训练再猛，也补不回一阶段覆盖面的巨大缺口。

怎么做

  • 轻质量过滤 + 重采样（幂律 γ≈0.73）
  • 分 domain 去重阈值，保护靠重复强化的能力
  • 长尾簇：覆盖一半语义簇可能只占 17% 文档——性价比高
  • 警惕：后期 loss 降最快的 Top10% 里，约 66% 是表格/模板/机器生成——记忆先变强
「平滑的 scaling 曲线底下，很大一块是模板识别能力的增长，而不是推理。」 来源 · P1 周报 一阶段 · 后期 loss 加速分析

后训练 · Post-training

底座训完了，还要「教会怎么跟人说话」

可以把预训练 + 中训练想成「把书写进脑子」；后训练是「练习考试答题卡怎么填、怎么礼貌地回答、错了怎么改」。 没有后训练，模型可能很博学，但不会按你的指令稳定输出。

文中橙色虚线词可以点击，会弹出人话解释（也可用上方「术语表」整页查阅）。

1. SFT 监督微调

准备大量「问题 → 理想回答」对，让模型模仿。作用：学会聊天格式、工具调用写法、 何时输出思考、中英切换等。你们周报里的「伴生 SFT / 班车」就是：中训练跑一段， 用固定后训练配方评一次，看底座有没有真正变强。

2. 偏好对齐（RLHF 等）

人不只给标准答案，还给「哪个更好」的偏好；或用奖励模型 / 规则打分， 再用强化学习（常见如 PPO、DPO 一类）继续调。作用：更听话、更安全、更少胡编乱造的表达。

3. 专项 RL / 工具 RL

对代码、数学、搜索 Agent 等，用可自动判对错的环境做强化：做对给奖、做错惩罚。 这是「会刷题 / 会改仓库」变强的常见后半段，和中训练里的轨迹数据前后呼应。

和中训练的分工

中训练：能力与知识密度

  • 加长上下文、Agent 轨迹、STEM 题、知识改写
  • 关心 val loss、domain bench、合版配比
  • 产出：更强的「底座 checkpoint」
后训练：行为与产品形态

后训练：交互与对齐

  • 对话模板、安全、拒答、工具格式
  • 关心指令遵循、真人偏好、线上坏 case
  • 产出：能上线给用户用的助手
为什么周报总提「以 SFT 结论为主」 小模型上的 ICL（尤其 0/1-shot）波动大，有时会「假崩塌」。中训练数据是否真有效， 往往要过一遍固定班车 SFT 再看：如果 SFT 后能力回来了，多半是评测方式问题，不是底座训废了。

内部经验 · 脱敏

内部周报反复出现的硬 Insight

这些不是口号，是已经付出实验成本的结论。训练 1T 时，把它们当成默认检查项。

01

重复不总是冗余

统一阈值去重会超额删竞赛代码；同源 Agent 轨迹两种加工可互补。先按 domain / 来源分层，再谈删多少。

02

模型变大，先变强的常常是记忆

后期 loss 加速数据里学科内容不到 5%。别把 val loss 下降全理解成「更会推理」。

03

评测体系是最大不确定性

GPQA 贴地板、长文生产 bench 均长只有 15K、小模型 few-shot 不置信、ladder 分辨率不足。优先投资 val loss 与能力打标。

04

配比是零和博弈

每一版合版都在描述谁被挤占。总预算固定时，数据工作的实质是分配，不是无限新增。

05

造上下文 > 再筛一层

PR 相关文件、release mask 上下文、长文 UUID 链、STEM 数据库改写——收益越来越多来自组织形式。

06

以 SFT / val loss 裁决，不盲信 ICL

Code ICL「雪崩」在 SFT 后消失；MRCR 上 ICL 与 SFT 可反向。小模型 0/1-shot 尤其不可靠。

07

短训看不到的风险，长跑才暴露

500B decay 不够；1.1T 后趋势才分离。合版要预留真正的长训窗口，并用非生产周期做周期性消融。

06 · 开干清单

训练 1T 之前，勾完这些再烧卡

按顺序勾。勾不完说明还没准备好上生产规模。

  • 能力目标与「不能掉点」的 bench 清单已书面确认
  • 一阶段数据：去重策略分 domain 定稿；采样表（STEM / 热门 / 长尾）可复现
  • 小 ladder + val loss 能区分你要试的配方差异（否则先升级评测）
  • 六大 topic 各有 owner、交付量、专项 bench、已知风险（垂类去重、commit 管线、1M 短板…）
  • 合版 Exp 路径写清；伴生 SFT 班车与 ICL 协议冻结
  • 32k → 256k → 1M 节奏与 VLM 混训比例已对齐生产日历
  • 长跑 derisk：Agent/长文持续 scale；无静默坏 bin；镜像版本锁定
  • 泄题检测、回流 special token 清洗、质量模型准召过线
  • 1T 训练：并行策略、checkpoint、存储带宽、故障恢复演练通过
  • 后训练班车与 Midtrain 评测归因口径一致
